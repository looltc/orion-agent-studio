# Orion Studio 用户体验设计文档

版本：v1.0
生效日期：2025-07
适用产品：Orion Agent Studio（桌面端 + Web 端）

---

## 一、设计原则

### 1.1 可预测性
用户操作应有明确的反馈。按钮点击后有视觉响应，RPC 调用有 loading/成功/失败 状态，系统状态变化有通知。

### 1.2 容错性
所有破坏性操作（删除 Agent、删除 Provider、清空会话）**必须**有确认步骤。不能用 `window.confirm()`（破坏深色主题），必须用应用内自定义弹窗。

### 1.3 系统状态可见性
连接状态、任务执行状态、RPC 调用状态**始终**对用户可见。不要让用户在不确定中猜测。

### 1.4 渐进式引导
新用户首次打开应用时，应有明确的下一步引导，而不是空白页面。

## 二、交互规范

### 2.1 破坏性操作确认

**规范**：所有 `delete` / `清空` / `移除` 操作，必须弹出确认弹窗，包含：
- 明确的警告文案（"确定要删除 Agent「{name}」吗？"）
- 后果说明（"此操作不可撤销"）
- 两个按钮：「取消」（次按钮）+ 「删除」（红色主按钮）

**涉及位置**：
- `DashboardPage.tsx：删除 Agent
- `ProvidersPage.tsx：删除 Provider`
- `AgentWorkspacePage.tsx：清空会话（当前用了 `window.confirm()`，需改为自定义弹窗）

### 2.2 RPC 调用反馈

**规范**：

| 场景 | 反馈方式 |
|------|----------|
| 调用中 | 按钮 `disabled` + spinner 图标 + 文字变为"处理中…" |
| 调用成功 | 弹窗自动关闭 + 页面数据刷新 + 上方短暂显示绿色成功提示（2 秒后自动消失）|
| 调用失败 | 表单下方红色文字提示具体错误原因（不要用 `console.warn` 代替 UI 反馈）|

**涉及位置**：`agentStore.ts` 所有 RPC 调用、`DashboardPage.tsx`、`ProvidersPage.tsx`、`AgentWorkspacePage.tsx`

### 2.3 空状态引导

**规范**：空状态不能只写"暂无数据"。必须有：
- 图标（已有）
- 引导文案（说明可以做什么）
- **行动按钮**（直接放在空状态里，不要让用户去找）

**涉及页面**：
- Dashboard（无 Agent 时）：保留"新建 Agent" 按钮（已有 ✅）
- ProvidersPage（无 Provider 时）：保留"添加 Provider" 按钮（已有 ✅，但可增加说明文案）
- AgentWorkspacePage（首次对话）：增加示例提示词，如"试试：帮我分析这段代码的性能瓶颈"

### 2.4 连接状态反馈

**规范**：
- 连接断开时，页面顶部显示 `ConnectionBar`（已有 ✅）
- 重连中：ConnectionBar 显示"正在重新连接…" + spinner 动画（已有 ✅）
- **重连成功**：短暂显示绿色"已连接" 提示条，1.5 秒后自动消失
- 输入区：daemon 未连接时，输入框 `disabled` + 灰色背景 + 提示文字"请先连接 Daemon"

## 三、信息架构

### 3.1 侧边栏导航

**当前问题**：侧边栏底部显示 `Daemon :9877`，这是硬编码文本，不反映真实连接状态。

**修正**：移除硬编码文本，改为显示连接状态徽章（已经在 `ConnectionBar` 组件中有实现，需整合进来）。

**侧边栏路由对齐**：
| 侧边栏项目 | 对应路由 | 状态 |
|---------------|----------|------|
| 仪表盘 | `/` | ✅ 已对齐 |
| 审计日志 | `/audit` | ✅ 已对齐 |
| LLM 提供者 | `/providers` | ✅ 已对齐 |
| 设置 | `/settings` | ✅ 已对齐 |
| Agent 工作区 | `/agent/:id` | ❌ 侧边栏无入口，只能通过 Dashboard 点击进入 |

### 3.2 页面标题规范

**问题**：各页面标题字号不一致（Dashboard 用 `text-2xl`，其他页面用 `text-xl`）。

**规范**：所有页面主标题统一使用 `text-xl font-semibold`（1rem / 16px）。

## 四、无障碍（Accessibility）

### 4.1 表单标签关联

**问题**：所有 `<input>` 的 `<label>` 是兄弟节点，但未用 `htmlFor` / `id` 关联，点击标签无法聚焦到输入框。

**修正方式**：每个表单字段改为：
```jsx
<label htmlFor="agent-name" className="...">名称</label>
<input id="agent-name" ... />
```

### 4.2 弹窗焦点管理

**问题**：弹窗打开时，焦点可以逃逸到背景元素（无障碍失败）。

**修正方式**：弹窗打开时，用 `focus-trap` 逻辑（或 `useRef` + `keydown` 监听 Tab/Shift+Tab）把焦点限制在弹窗内。弹窗关闭时，焦点回到触发按钮。

### 4.3 图标按钮 `aria-label`

**问题**：`Trash2`、`Settings`、`ArrowLeft` 等图标按钮只有 `title`，屏幕阅读器无法识别。

**修正方式**：所有图标按钮增加 `aria-label="删除 Agent"` 属性。

## 五、视觉一致性

### 5.1 按钮样式统一

| 按钮类型 | 样式类 | 使用场景 |
|----------|----------|----------|
| 主操作（确认、创建）| `bg-orion-600 hover:bg-orion-700 text-white` | 弹窗底部确认按钮 |
| 次按钮（取消）| `border border-surface-200 dark:border-surface-700 text-surface-600 dark:text-surface-400` | 弹窗底部取消按钮 |
| 图标按钮（悬停可见）| `p-1.5 rounded-lg text-surface-400 hover:text-orion-600 dark:hover:text-orion-400` | 卡片右上角操作 |

### 5.2 圆角半径统一

| 元素 | 应使用的圆角 | 当前问题 |
|------|---------------|----------|
| 卡片、弹窗 | `rounded-xl`（12px）| 部分卡片用了 `rounded-lg` |
| 输入框、按钮 | `rounded-lg`（8px）| ✅ 已统一 |
| 胶囊标签、开关 | `rounded-full` | ✅ 已统一 |

## 六、待实现的用户流程

### 6.1 首次使用引导流程

1. 用户打开应用 → 检测到无 Agent → Dashboard 空状态引导
2. 点击"新建 Agent" → 表单弹窗 → 如果检测到无 Provider → 提示先配置 Provider
3. Provider 配置完成 → 回到 Agent 创建 → 填写后创建成功
4. 点击 Agent 卡片 → 进入工作区 → 输入框可用 → 输入目标开始任务

### 6.2 错误处理流程

1. RPC 调用超时（30 秒）→ 输入框上方红色提示条："连接超时，请检查 Daemon 是否正常运行"
2. 创建 Agent 失败 → 弹窗内红色提示："创建失败：{具体原因}"，弹窗不关闭，用户可修改后重试
3. 后端返回 `error` 字段 → 在对应页面顶部红色提示条显示，5 秒后自动消失
